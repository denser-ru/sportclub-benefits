# Sportclub Benefits API & App

**Full-stack-проект, разработанный в рамках технического задания. Демонстрирует создание отказоустойчивого бэкенд-сервиса на FastAPI и современного фронтенд-приложения на React, объединенных в единую систему с помощью Docker.**

---

## 🚀 Как запустить

Это предпочтительный способ запуска, который поднимает всю инфраструктуру одной командой.

**Требования:**
*   Docker
*   Docker Compose

### 1. Локальная разработка (с Hot-Reload)

Этот режим идеально подходит для разработки, так как включает автоматическое обновление кода без перезапуска контейнеров.

1.  Клонируйте репозиторий:
    ```bash
    git clone <repository_url> sportclub-benefits
    cd sportclub-benefits
    ```

2.  Создайте файл `.env` на основе примера:
    ```bash
    cp .env.example .env
    ```
    *В этом файле можно изменить порты, если они заняты.*

3.  Запустите сервисы:
    ```bash
    docker compose -f docker-compose.yml -f docker-compose.override.yml up --build
    ```

*   **Frontend** будет доступен по адресу: `http://localhost:5173` (или порт из `.env`)
*   **Backend API** будет доступен по адресу: `http://localhost:8000` (документация API: `http://localhost:8000/docs`)

### 2. Запуск с эмуляцией внешнего API (Mock-режим)

Если реальное API `sportclub.com.ar` недоступно, используйте этот режим. Он запускает локальный mock-сервер.

```bash
docker compose -f docker-compose.yml -f docker-compose.override.yml -f compose.mock.yml up --build
```

### 3. Запуск в режиме "Production"

Эта команда симулирует запуск в продакшене: используются оптимизированные, легковесные образы без инструментов для разработки.

```bash
docker compose -f docker-compose.yml up --build -d
```
*(флаг `-d` запускает контейнеры в фоновом режиме)*

## ✅ Как запустить тесты

Тесты запускаются в изолированных Docker-контейнерах, что гарантирует консистентность окружения.

**Запуск тестов для Backend:**
```bash
docker compose -f docker-compose.yml -f docker-compose.override.yml run --rm backend-tests pytest
```

**Запуск тестов для Frontend:**
```bash
docker compose -f docker-compose.yml -f docker-compose.override.yml run --rm frontend-tests npm test
```

## 🏛️ Архитектура и принятые решения

Проект спроектирован с упором на надежность, масштабируемость и лучшие практики разработки.

### Backend (Python/FastAPI)

*   **Прагматичная Clean Architecture:** Логика четко разделена на слои:
    *   `api/`: **Presentation Layer** – обработка HTTP-запросов.
    *   `services/`: **Application Logic Layer** – оркестрация бизнес-процессов.
    *   `clients/`: **Infrastructure Layer** – инкапсуляция работы с внешним Sportclub API.
    *   `domain/`: **Domain Layer** – Pydantic-модели для строгой типизации и валидации данных.
*   **Отказоустойчивость:** Реализован глобальный обработчик ошибок. Если внешнее API недоступно, наш сервис не падает с ошибкой 500, а вежливо отдает `503 Service Unavailable`, логируя инцидент.
*   **Конфигурация:** Настройки (URL, порты) управляются через `.env` файлы с помощью `pydantic-settings`, что позволяет гибко настраивать приложение для разных окружений.
*   **Адаптивное логирование:** Система логирования автоматически меняет уровень детализации: подробные трейсбеки в `DEBUG`-режиме для разработки и лаконичные `INFO`/`WARNING` сообщения для продакшена.

### Frontend (React/TypeScript/Vite)

*   **Современный стек:** Использование React, TypeScript, Vite, Zustand и React Router DOM.
*   **Эффективное управление состоянием (Zustand):**
    *   Состояние разделено на гранулярные срезы, а компоненты используют селекторы для подписки только на необходимые им данные. Это **предотвращает лишние ререндеры**.
    *   Реализована **"cache-first"** стратегия: данные для детальной страницы сначала ищутся в кеше, и только при их отсутствии отправляется сетевой запрос.
    *   Функция "Избранное" сохраняется в `localStorage` с помощью `persist` middleware, обеспечивая сохранность данных между сессиями.
*   **Оптимизация производительности:**
    *   Фильтрация списка преимуществ мемоизируется с помощью `useMemo`.
    *   Для поля поиска применен кастомный хук `useDebounce`, который откладывает вызов фильтрации, снижая нагрузку на приложение при быстром вводе.
*   **Доступность (Accessibility, A11y):** Применены базовые, но ключевые практики доступности: семантическая разметка ( `<article>`, `<section>`), `alt`-атрибуты для изображений, `aria-` атрибуты и связь `<label>` с полями ввода.

### DevOps и контейнеризация

*   **Multi-stage Dockerfiles:** И для бэкенда, и для фронтенда используются многоэтапные сборки. Это создает минимальные и безопасные production-образы, очищенные от сборочных зависимостей.
*   **Разделение сред (Dev/Prod):** Использование `docker-compose.override.yml` позволяет иметь разные конфигурации для разработки (с hot-reload) и продакшена, что является лучшей практикой.
*   **Healthchecks:** В `docker-compose.yml` настроены проверки состояния для бэкенд-сервиса, что гарантирует правильный порядок запуска контейнеров.
*   **Безопасность:** Бэкенд-сервис в финальном образе запускается от имени не-рутового пользователя (`appuser`).
